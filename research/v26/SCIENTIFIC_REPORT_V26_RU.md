## 2. Новая конечномерная теорема о минимальном пространстве
На PL16/W17 по опубликованным E-only данным:
`dim W17=17`, `rank(P E0 P)=2`, `rank(E0 P)=17`. Для `K=ker(P E0 P)`, `dim K=15`, `P E0 K=0`, а `E0|K` инъективен. Следовательно

```
dim span(W17, E0 K) = 17+15 = 32.
```

Также десять архивных независимых `[E0,Er] Ω` лежат вне W17, откуда минимальное пространство для W17 и этих коммутаторов имеет размерность 27. Без знания их перекрытия с `E0 K` нельзя требовать 42; совместная строгая нижняя граница только 32. Существующее W43 имеет размерность 43, но не доказано инвариантным относительно `H_E+H_L+R`.

Из `σmin(E0|W17)=2.0081387278495684`:
`||(I-P) E0|K||_F >= 7.777487849835527`; с евклидовым коэффициентом 2/3: `>=5.184991899890351`.
Если операторная погрешность десятиранговой E-only карты меньше `1.324189319007516`, её ранг сохраняется; для равномерной поколоночной погрешности достаточно `δ<1.324189319007516/√10=0.4187454301331`. Это условия, НЕ измерения реальной ошибки.

## 3. Высокоточная альтернатива почти вырожденному Gram-sum
Исходный `scripts/bqg_he_sine_true_coherent_charge_orientation.py` использует блочную `np.einsum` суммирования попарных Gram-элементов, а затем `max(0.,float(total.real))`. Такой алгоритм может потерять чрезвычайно малую норму при сильном сокращении. В локальном синтетическом примере с тремя коэффициентами `1e8, 1e-8, -1e8` Gram-сумма float64 дала **0**, а high-precision прямое сложение полных комплексных амплитуд дало квадрат нормы
`1.0000000000000000418451216602569457884e-16`.
Независимая проверка на точных бинарных дробях подтвердила эту величину для исходных **уже округлённых двоичных входов**.

Новый `scripts/v26_direct_branch_norm.py` группирует ортогональные spin-сектора и строит каждую полную тензорную координату, складывает комплексные вклады с `mpmath`, и лишь затем возводит в квадрат. Для малых тестов добавлен точный рациональный оракул. Выходы после применения алгоритма к исходным SU2 amplitudes НЕ станут автоматически точными физическими результатами: исходная амплитуда и её recoupling могут уже содержать ошибки double precision.

## 4. Настоящие 12 ориентированных H_E sine: обнаружен предел scalar-only метода
Исходный реальный вычислительный журнал K5: Git blob `078c311c74c0131d09ecacefe57b9eb7735b30ea`, GitHub Actions run `42136642363`. На каждом из 12 ориентированных расчётов было 6144 исходных факторизованных ветвей. Для 0,3,6 численное сокращение помечено как `CANCELLATION_DOMINATED_NOT_CERTIFIED`. Для ориентации 6 `incoherent2/raw2 ≈ 5.90×10^17` (около 59 бит потери масштабов); это диагностический показатель, НЕ сертифицированная оценка forward error.

Опубликованные raw2 и projected2 для нескольких ориентаций дают `projected2>raw2` на масштабе округления. Пусть каждое истинное квадрат-нормированное число отличается от его публикации не более `η`, а все 12 проецируются одним и тем же ортогональным P. Тогда монотонность P требует
`η >= max_i max(0, projected2_i-raw2_i)/2=3.0531133177191805e-16`.

Условно по неравенству треугольника
```
||(I-P)sum_i psi_i|| <= Σ_i sqrt(max(0,raw2_i-projected2_i)+2η).
```
При минимально возможном согласованном `η` правая часть равна `2.968242024292176e-7`. Это верхняя **условная** граница, не измеренная величина утечки. По только таким опубликованным scalar norms данный метод не сертифицирует утечку `<1e-8`. При этом истинная утечка может быть нулевой. Нужны сложение **комплексных состояний до проекции**, единая Hilbert norm, и независимый error budget.

## 5. Original-producer execution driver
`scripts/v26_original_charge_highprecision.py` вызывает **оригинальный** производственный `H_E^{sine}` SU(2) скрипт и заменяет только вычисление нормы raw Gram на прямое high-precision суммирование. Проверяет исходный Git commit, SHA и чистоту tracked worktree. Драйвер не запускается успешно при отсутствии оригинального производственного кода и не подменяет её mock-выходами. Локальный контейнер не имел полного аутентифицированного checkout; поэтому настоящие ориентации 0,3,6 **не были пересчитаны**.

Для исходной ветки и достаточной оперативной памяти:
```bash
python -m pip install numpy mpmath
python -m unittest discover -s tests -p 'test_v26_highprecision_charge.py' -v
python scripts/v26_original_charge_highprecision.py --orientation 6 --source 1 --target 0 --Jmax2 3 --digits 80 --output artifacts/v26/orient6.json
```
Далее 0 и 3; следует контролировать размеры тензорного произведения, превышение которых вызывает явный отказ. Только после этого допустимо обсуждать actual SU(2) coherent raw norms. Это **план запуска**, не выполненный расчёт.
